How to read this report
  * No culprit is a valid result, not a gap. No installed mod could be linked to an entry from either the log line or its stack; that does not prove the game is at fault, because a mod can act indirectly through a Harmony patch or leave broken state behind. The manager does not name a mod by guesswork.
  * A repeat counter means one recurring scenario, not that many separate failures. Each card shows the first and last occurrence; Distinct values tells how many different variants were merged, and Values lists them (up to 20). Look at what was happening in game at the first occurrence.
  * When a class is missing, the game reports it through three independent mechanisms, and the same class name can appear under more than one with a different count. The XUi controller factory resolves window controllers; Type.GetType() resolves dialog, AI and condition classes; and action-class registration (for example 'NPCNoVoiceTag') resolves entity actions. They are separate lookup paths of one problem, not duplicated errors and not proof of separate faults.
